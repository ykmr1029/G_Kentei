# 第2章 人工知能をめぐる動向 — 詳細解説（探索・推論編）

## 2-1. 探索（Search）

---

### 2-1.1. 探索と推論

第一次AIブーム（1950年代後半〜1960年代）では、コンピュータが「探索」と「推論」によって問題を解くアプローチが研究されました。

**探索（Search）**とは、問題の解を求めるために考えられる手順を系統的に調べることです。  
**推論（Reasoning）**とは、既知の知識から新たな結論を論理的に導き出すことです。

---

### 2-1.2. 問題のツリー構造への変換

迷路やゲームのような問題は、**ツリー構造（探索木）** に変換することでコンピュータが処理できるようになります。

| 要素 | 説明 |
|------|------|
| **ノード（節）** | 状態（迷路の交差点、ゲームの盤面など） |
| **エッジ（辺）** | 遷移（移動・行動） |
| **ルートノード** | 初期状態 |
| **ゴールノード** | 目標状態 |

#### 迷路のツリー構造化

迷路は以下の3種類のノードで表現できます：

| 種類 | 説明 |
|------|------|
| **分岐点** | 複数の道に分かれる交差点 |
| **道** | 分岐点間のパス |
| **終着点** | ゴールまたは行き止まり |

> ポイント: 迷路 → **分岐点・道・終着点**の3種類のノードでツリー化できる

---

### 2-1.3. 幅優先探索（BFS: Breadth-First Search）

**幅優先探索（BFS）** は、出発点から近いノード（浅い階層）を順番にすべて探索してから、より深い階層を探索するアルゴリズムです。

| 特徴 | 内容 |
|------|------|
| **最短経路** | 保証される（最短距離でゴールに到達） |
| **メモリ消費** | 多い（全ノードをキューに保持する必要あり） |
| **実装** | キュー（FIFO：先入れ先出し）を使用 |

**メリット**: 最短経路が必ず見つかる  
**デメリット**: メモリ消費が大きく、大規模な問題では現実的でない

---

### 2-1.4. 深さ優先探索（DFS: Depth-First Search）

**深さ優先探索（DFS）** は、一つの経路を末端（ゴールまたは行き止まり）まで探索してから、バックトラックして別の経路を探索するアルゴリズムです。

| 特徴 | 内容 |
|------|------|
| **最短経路** | 保証されない |
| **メモリ消費** | 少ない（1つ前のノードに戻るだけ） |
| **実装** | スタック（LIFO：後入れ先出し）を使用、または再帰 |

**メリット**: メモリ消費が少ない  
**デメリット**: 最短経路が保証されず、無限ループに注意が必要

#### BFS vs DFS まとめ

| 比較項目 | BFS | DFS |
|---------|-----|-----|
| 最短経路の保証 | **あり** | なし |
| メモリ消費 | 多い | **少ない** |
| データ構造 | キュー（FIFO） | スタック（LIFO）／再帰 |
| 適したケース | 最短路が必要なとき | メモリ節約が必要なとき |

> ポイント: **BFS = 最短経路保証・メモリ大** / **DFS = 最短経路なし・メモリ少**

---

### 2-1.5. 問題のバリエーション：ハノイの塔

**ハノイの塔（Tower of Hanoi）** は、探索問題の代表例の一つです。

- 3本のポールと大きさの異なる円盤で構成
- 一度に1枚の円盤しか動かせない
- 小さな円盤の上に大きな円盤を置けない

**コンピュータでの表現**：  
各円盤がどのポールにあるかを座標（状態）で表現し、迷路と同様の**探索木問題**として解きます。

## 2-2. 推論・知識と行動計画

---

### 2-2.1. STRIPS（スタンフォード研究所問題解決システム）

**STRIPS（Stanford Research Institute Problem Solver）** は、ロボットの行動計画（プランニング）を定式化した手法です。

| 要素 | 説明 |
|------|------|
| **前提条件（Precondition）** | 行動を実行するために必要な条件 |
| **行動（Action）** | 実行する操作 |
| **結果（Effect/Postcondition）** | 行動後の状態変化 |

この3要素で行動を定義することで、ロボットが目標を達成するための計画を自動生成できます。

**プランニング（Planning）**とは、ロボットが目標を達成するために実行すべき行動の順序（計画）を自動的に生成することです。

> ポイント: STRIPS = **前提条件・行動・結果** の3要素でロボットの行動を定義

---

### 2-2.2. SHRDLU（シュルドゥル）

**SHRDLU** は1968〜1970年にテリー・ウィノグラード（Terry Winograd）が開発した「積み木の世界（Blocks World）」システムです。

| 項目 | 内容 |
|------|------|
| 開発者 | **テリー・ウィノグラード（MIT）** |
| 開発年 | **1968〜1970年** |
| 特徴 | 自然言語でロボットに積み木の操作を指示できる |
| 意義 | STRIPSの研究ベースとなり、Cycプロジェクトへと引き継がれた |

> ポイント: **SHRDLU = テリー・ウィノグラード, 1968〜1970年, 積み木の世界**

---

### 2-2.3. Cycプロジェクト

**Cycプロジェクト** は、SHRDLUの後継として人間の常識的知識（コモンセンス）を大規模にコンピュータに取り込む研究プロジェクトです。

- 自然言語理解には常識的知識が不可欠という認識から生まれた
- 大量の常識的知識をデータベース化することを目指す

> ポイント: **Cyc = 人間の常識的知識をコンピュータに格納するプロジェクト**

---

## 2-3. ゲームAI

---

### 2-3.1. ヒューリスティックな知識

ゲームAIの探索において、すべての手を計算するのは現実的ではありません。そこで**ヒューリスティックな知識**（経験則）を用いて探索を効率化します。

**ヒューリスティックな知識**とは、既知の経験や知識をもとに探索の優先度をつけるための知識です。ボードゲームでは「盤面の有利・不利を数値で評価する**評価関数**」がこれにあたります。

---

### 2-3.2. Mini-Max法

**Mini-Max法** は、2人のプレイヤーが交互に手を選ぶゲームで最善手を選ぶアルゴリズムです。

| ターン | 戦略 |
|--------|------|
| **自分のターン** | スコアが **最大（Max）** になる手を選ぶ |
| **相手のターン** | 自分のスコアが **最小（Min）** になる手を相手が選ぶと仮定 |

数手先の末端状態を評価関数でスコア化し、そこから逆算（バックトラック）して現在の最善手を決定します。

**デメリット**: 全候補を評価するため計算量が非常に多い

> ポイント: Mini-Max法 = **自分Max・相手Min を数手先から逆算**して最善手を決定

---

### 2-3.3. αβ法（Alpha-Beta Pruning）

**αβ法** は、Mini-Max法を改良したアルゴリズムで、明らかに選ばれない枝を**枝刈り（Pruning）** して探索量を削減します。

| 特徴 | 内容 |
|------|------|
| **結果** | Mini-Max法と**同じ最善手**が得られる |
| **効率** | 探索量を大幅に削減できる |
| **依存性** | 枝刈りの精度は評価関数の質に依存 |

> ポイント: αβ法 = Mini-Max法の改良版。**同じ結果をより少ない計算で**実現

---

### 2-3.4. AlphaGoとモンテカルロ木探索

**AlphaGo** は2016年3月、DeepMind社が開発した囲碁AIで、韓国のプロ棋士イ・セドルを5局中4勝で破りました。

| 項目 | 内容 |
|------|------|
| 開発 | **DeepMind**（Googleの子会社） |
| 対戦相手 | **イ・セドル**（韓国プロ棋士） |
| 結果 | AlphaGoが**4勝1敗** |
| 技術 | ディープラーニング × **モンテカルロ木探索（MCTS）** |
| 年 | **2016年3月** |

#### 囲碁の難しさ

- 囲碁の状態空間は約**10の360乗**通り（チェス：約10の120乗）
- 盤面の有利・不利を評価する評価関数が作りにくい
- 従来のMini-Max法やαβ法だけでは対処困難

#### モンテカルロ木探索（MCTS）

**モンテカルロ木探索**とは、ランダムシミュレーション（プレイアウト）を多数実行し、その統計結果から最善手を推定する手法です。

- 評価関数を必要とせず、シミュレーション結果の勝率で判断
- AlphaGoではMCTSにディープラーニングを組み合わせてさらに精度を向上

#### Deep Blue（参考）

| 項目 | 内容 |
|------|------|
| 開発 | **IBM** |
| ゲーム | チェス |
| 対戦相手 | **ガルリ・カスパロフ**（世界チャンピオン） |
| 年 | **1997年** |
| 手法 | Mini-Max法 + αβ法 + 評価関数 |

> ポイント: **AlphaGo = DeepMind, 2016年, イ・セドル** / **Deep Blue = IBM, 1997年, カスパロフ**

## 2-4. 人工無能とエキスパートシステム

---

### 2-4.1. 人工無能（Chatterbot）

**人工無能**とは、特定のルールやパターンマッチングに従って機械的に会話を行うプログラムです。内容を「理解」しているわけではありません。現代のチャットボットの原型とも言えます。

#### ELIZA（エライザ）

| 項目 | 内容 |
|------|------|
| 開発者 | **ジョセフ・ワイゼンバウム（Joseph Weizenbaum）** |
| 開発年 | **1964〜1966年** |
| 機関 | MIT |
| 手法 | パターンマッチングによる会話 |

ELIZAは「パターンに応じて決まった返答をする」だけでしたが、ユーザーが「本当に人間と話している」と感じるほどの会話を実現しました。

#### イライザ効果（ELIZA Effect）

**イライザ効果**とは、人工無能との会話で、まるで本当に人間と会話しているような錯覚に陥る現象です。

- ワイゼンバウム自身がこの効果に驚き、コンピュータへの過度な依存を警告するようになった
- 現代のチャットボット・AIアシスタントにも同様の効果が見られる

> ポイント: **ELIZA = 1964〜1966年、ジョセフ・ワイゼンバウム（MIT）**  
> ポイント: **イライザ効果 = 人工無能に人間を感じる錯覚現象**

---

### 2-4.2. エキスパートシステム（Expert System）

**エキスパートシステム**は、専門家の知識をルールとしてデータベース化し、そのルールに基づいて推論・判断を行うシステムです。第二次AIブームの中心的な技術です。

#### MYCIN（マイシン）

| 項目 | 内容 |
|------|------|
| 開発機関 | **スタンフォード大学** |
| 開発年 | **1970年代** |
| 目的 | 血液中のバクテリアの診断支援 |
| 仕組み | 約**500のルール**に基づき処方を決定 |
| 正答率 | **69%**（一般医師水準を超えるが、専門医の**80%**には届かない） |

#### エキスパートシステムの限界

- **知識獲得のボトルネック**: 専門家の暗黙知の形式化が困難（→ 1-4.1参照）
- 知識の蓄積・管理コストが膨大
- 知識が増えると矛盾が生じやすくなる
