# 第2章 人工知能をめぐる動向（探索・推論） — 詳細解説

## 2-1. 探索の基礎

---

### 2.1.1. 迷路とツリー構造

コンピュータは迷路を**ツリー構造（探索木）**に変換して解きます。

迷路の構成要素を3種類のノードに分類します。

| ノードの種類 | 内容 |
|-------------|------|
| **分岐点** | 経路が2方向以上に分かれる点 |
| **道** | 分岐点を結ぶ経路（エッジ） |
| **終着点** | ゴールまたは行き止まり |

迷路の出発点をルートノードとし、各分岐点をノード、道をエッジとして木構造を作成します。このツリー構造に対して探索アルゴリズムを適用することで、コンピュータが迷路を解けるようになります。

> ポイント: 迷路をコンピュータで解くには**ツリー構造への変換**が必要。**分岐点・道・終着点**の3種類のノードに分類する。

---

### 2.1.2. 幅優先探索（BFS: Breadth-First Search）

**幅優先探索**は、出発点から近いノードを順に（横方向に）探索していく方法です。

| 特徴 | 内容 |
|------|------|
| 探索順序 | 同じ深さのノードをすべて探索してから次の深さへ進む |
| **メリット** | **最短距離（最短経路）を保証**する |
| **デメリット** | **メモリ消費が多い**（全ノードをメモリに保持する必要がある） |

> ポイント: BFS = **最短経路を保証** / **メモリ消費大**

---

### 2.1.3. 深さ優先探索（DFS: Depth-First Search）

**深さ優先探索**は、1つの経路を末端（行き止まり/ゴール）まで探索してから、一歩戻って別の経路を探索する方法です（バックトラック）。

| 特徴 | 内容 |
|------|------|
| 探索順序 | 1つの経路を末端まで辿ってからバックトラック |
| **メリット** | **メモリ消費が少ない**（現在の経路のみ保持すればよい） |
| **デメリット** | **最短経路を保証しない** |

> ポイント: DFS = **メモリ消費小** / **最短経路を保証しない**

---

### 2.1.4. BFSとDFSの比較

| 項目 | BFS（幅優先探索） | DFS（深さ優先探索） |
|------|:----------------:|:------------------:|
| 最短経路の保証 | **あり** | なし |
| メモリ消費 | **多い** | **少ない** |
| 探索方向 | 横（同じ深さを先に） | 縦（深く潜る） |
| 特徴的なケース | 複雑な迷路ではメモリ不足になりやすい | 運が悪ければ遠回りになる |

---

### 2.1.5. A*アルゴリズム（A-Star）

**A*アルゴリズム**は、BFSとDFSの長所を組み合わせ、**ヒューリスティック（経験的知識）を活用して効率よく最短経路を求める**アルゴリズムです。

#### 評価関数

$$f(n) = g(n) + h(n)$$

| 変数 | 内容 |
|------|------|
| **g(n)** | 出発点からノード n までの実際のコスト |
| **h(n)** | ノード n からゴールまでの**推定コスト**（ヒューリスティック関数） |
| **f(n)** | 総評価値。これが小さい順にノードを探索 |

ヒューリスティック関数 h(n) が適切（過大評価しない「許容的」な関数）であれば、A*アルゴリズムは最短経路を効率よく発見できます。

> ポイント: A*アルゴリズム = **g(n) + h(n)** の評価関数を使ってBFS + ヒューリスティックで最短経路を効率探索

---

### 2.1.6. ハノイの塔と探索問題

**ハノイの塔**は、3本のポール（A・B・C）と複数の円盤を使ったパズルです。

- 「各円盤がどのポールにあるか」という**状態（座標）**で表現することで、迷路と同様の**探索木問題**として解くことができます。
- 状態の数は円盤数が増えると指数的に増加します（3枚なら27通り）。

---

## 2-2. ゲームAIと探索

---

### 2.2.1. ヒューリスティックな知識

**ヒューリスティックな知識**とは、既知の経験・知識をもとに探索を効率化するための知識のことです。

ボードゲームAIでは、すべての手を末端まで探索することは計算量的に不可能です（チェスは約10の120乗通り、囲碁は約10の360乗通り）。そこでヒューリスティックな知識（評価関数）を使って盤面の有利・不利を評価し、探索候補を絞り込みます。

---

### 2.2.2. Mini-Max法

**Mini-Max法**は、2人対戦ゲームでの最善手を求めるアルゴリズムです。

| ターン | 戦略 |
|--------|------|
| **自分のターン（Max）** | スコアが**最大（Max）**になる手を選ぶ |
| **相手のターン（Min）** | 相手が選ぶと自分のスコアが**最小（Min）**になる手を想定 |

数手先まで読み、末端の評価値から**逆算（バックプロパゲーション）**して最善手を決定します。

| 特徴 | 内容 |
|------|------|
| 原理 | 自分Max・相手Min を数手先から逆算 |
| **デメリット** | 全候補を評価するため非効率（計算量が大きい） |

---

### 2.2.3. αβ法（Alpha-Beta Pruning）

**αβ法**は**Mini-Max法の改良版**です。「明らかに選ばれない枝（手）を枝刈り（Pruning）する」ことで、探索量を大幅に削減します。

| 項目 | 内容 |
|------|------|
| ベース | Mini-Max法 |
| 改良点 | **枝刈り**（明らかに選ばれない候補を探索しない） |
| **結果の質** | Mini-Max法と**同等の最善手**を得られる |
| **デメリット** | 枝刈りの精度が評価関数の質に依存 |

> ポイント: αβ法 = Mini-Max改良版 / 枝刈りで効率化 / **結果の質はMini-Maxと同等**

---

### 2.2.4. モンテカルロ木探索（MCTS: Monte Carlo Tree Search）

**モンテカルロ木探索**は、ランダムシミュレーション（モンテカルロシミュレーション）を繰り返すことで、有望な手を絞り込む探索手法です。

#### MCTSの4ステップ

| ステップ | 名称 | 内容 |
|---------|------|------|
| 1 | **選択（Selection）** | 有望なノードを選択する |
| 2 | **展開（Expansion）** | 選択したノードに新しいノードを追加する |
| 3 | **シミュレーション（Playout）** | ランダムにゲームを終局まで実行する |
| 4 | **バックプロパゲーション（Backpropagation）** | 結果（勝敗）を上位ノードに反映する |

| 特徴 | 内容 |
|------|------|
| **メリット** | 詳細な評価関数がなくても機能する |
| **活用例** | AlphaGoの初期版でディープラーニングと組み合わせて使用 |

> ポイント: MCTS = **選択→展開→シミュレーション→バックプロパゲーション** / ランダムプレイアウトで有望な手を絞り込む

---

### 2.2.5. AlphaGo（アルファ碁）

| 項目 | 内容 |
|------|------|
| 開発 | **DeepMind**（Alphabet/Google傘下）社 |
| 出来事 | **2016年3月**、韓国のプロ棋士 **イ・セドル（Lee Sedol）** に4勝1敗で勝利 |
| 技術 | ディープラーニング（畳み込みニューラルネットワーク）＋ モンテカルロ木探索 |
| 意義 | 囲碁という超高難度ゲームでプロ棋士を初めて超えた歴史的な出来事 |

囲碁は約10の360乗通りの組み合わせがあり、従来のゲームAI（Mini-Max/αβ）での攻略は困難とされていました。AlphaGoはディープラーニングとMCTSを組み合わせることでこの課題を克服しました。

> ポイント: AlphaGo = **DeepMind** / **2016年3月** / **イ・セドル**に勝利

## 2-3. 知識表現とプランニング

---

### 2.3.1. STRIPS（ストリップス）

**STRIPS（Stanford Research Institute Problem Solver）**は、ロボットの行動計画（プランニング）を記述するためのフレームワークです。

#### STRIPSの3要素

| 要素 | 内容 |
|------|------|
| **前提条件（Precondition）** | この行動を実行するために必要な条件 |
| **行動（Action）** | 実行する動作 |
| **結果（Effect）** | 行動後の状態の変化 |

この3要素でロボットのすべての行動を定義し、目標状態に至る最適な行動計画を自動的に生成します。

> ポイント: STRIPS = **前提条件・行動・結果**の3要素でロボットの行動計画（プランニング）を立てる手法

---

### 2.3.2. SHRDLU（シュルドル）

| 項目 | 内容 |
|------|------|
| 開発者 | **テリー・ウィノグラード（Terry Winograd）** |
| 開発年 | **1968〜1970年** |
| 内容 | 「積み木の世界」でロボットに**自然言語**で指示を与えるシステム |
| 意義 | 限定された世界での自然言語理解を実証。STRIPSの研究ベースとなった |

SHRDLUは「積み木の世界」という限定された環境内で自然言語での指示（例:「赤い積み木を青い積み木の上に置け」）を理解・実行できることを示しました。その後のAIプランニング研究（Cycプロジェクトなど）に大きな影響を与えました。

> ポイント: SHRDLU = **テリー・ウィノグラード** / **1968〜1970年** / **積み木の世界**での自然言語指示

---

### 2.3.3. Cycプロジェクト

| 項目 | 内容 |
|------|------|
| 目的 | 人間の**常識的知識**をコンピュータに大規模に取り込む |
| 背景 | SHRDLUの後継として、より広い常識知識の表現を目指した |
| 課題 | 知識の量と複雑さが膨大で、完全な実現は困難 |

> ポイント: Cyc = **人間の常識的知識をコンピュータに取り込む**プロジェクト（SHRDLUの後継）

---

### 2.3.4. 前向き推論・後ろ向き推論

知識ベースシステム（エキスパートシステムなど）での2種類の推論方法です。

| 推論方式 | 推論の方向 | 説明 | 活用例 |
|---------|:--------:|------|--------|
| **前向き推論（Forward Chaining）** | 事実 → 結論 | 既知の事実にルールを適用して新たな事実・結論を導く | 症状が判明→病名を推定 |
| **後ろ向き推論（Backward Chaining）** | 目標 → 事実 | 目標（仮説・結論）から逆向きに必要な事実を確認する | 病名を仮定→症状を確認 |

> ポイント: 前向き推論 = **事実から結論**を導く / 後ろ向き推論 = **結論（仮説）から事実**を確認する

---

### 2.3.5. プランニング（Planning）

**プランニング**とは、ロボットや自律エージェントがどのように行動するかの計画を立てることです。STRIPSがプランニング表現の代表的な手法です。

---

## 2-4. 人工無能とイライザ効果

---

### 2.4.1. 人工無能（Artificial Stupidity）

**人工無能**とは、特定のルールや手順に従って機械的に会話を行うプログラムのことです。内容を「理解」しているわけではありません。

- チャットボットの原型とも言える
- 元祖は **ELIZA（エライザ）**

---

### 2.4.2. ELIZA（エライザ）とイライザ効果

| 項目 | 内容 |
|------|------|
| 開発者 | **ジョセフ・ワイゼンバウム（Joseph Weizenbaum）** |
| 開発年 | **1964〜1966年** |
| 仕組み | 特定のキーワードへのパターンマッチングで返答を生成 |
| 特徴 | 内容を「理解」せずに会話する人工無能 |

**イライザ効果（ELIZA Effect）**とは、ELIZAのような人工無能との会話で、まるで本当に人間と会話しているような錯覚に陥ることです。

開発者のワイゼンバウム自身がこの効果を観察し、コンピュータに意思決定を任せることの危険性を警告するようになりました。

> ポイント: ELIZA = **ジョセフ・ワイゼンバウム、1964〜1966年** / **イライザ効果** = 人工無能との会話で人間と話していると錯覚する現象

---

## 2-5. エキスパートシステム

---

### 2.5.1. MYCIN（マイシン）

**MYCIN**は、第二次AIブームを代表するエキスパートシステムです。

| 項目 | 内容 |
|------|------|
| 開発機関 | **スタンフォード大学** |
| 開発年 | **1970年代** |
| 目的 | 血液中のバクテリアの診断と適切な抗生物質の処方を支援 |
| 仕組み | **500のルール**による判断 |

#### MYCINの処方正答率

| 対象 | 正答率 |
|------|:------:|
| MYCIN | **69%** |
| 一般医師 | 約58% |
| **専門医** | **80%** |

MYCINは一般医師を上回る正答率（69%）を達成しましたが、専門医（80%）には届きませんでした。これはエキスパートシステムの**可能性（一般医師超え）と限界（専門医には届かない）**を同時に示す典型例です。

> ポイント: MYCIN = **スタンフォード大学** / **500のルール** / 正答率**69%**（一般医師超え・専門医は80%）
